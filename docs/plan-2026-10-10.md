### D. Pane chrome redesign (the pill)
Target, per Harold: in each pane's upper-left, a pill with `☰ menu · glyph+title · toolbar toggle · ×`. Group chrome keeps `×` and pop-out. Works on mobile and desktop and never disappears in small spaces.
- D1. **Decided (spike, 2026-10-10): tab-as-pill.** Do not hide the header. Set `singleTabMode: 'fullwidth'` and render the pill *inside* `ColoredTab`, so it sits on Dockview's real draggable tab and `TabDragHandler`/`PanelTransfer` keep working. A custom drag from arbitrary DOM is not possible: `LocalSelectionTransfer` is not exported from dockview-core and the bundled singleton is unreachable. Header is CSS-floated into the pane's upper-left with pointer-events scoped. Groups with ≥2 tabs degrade to normal tabs. Interactive children need `draggable={false}` + pointerdown stopPropagation. Dockview has no touch DnD at all, so mobile needs pill-menu items "Move to…" and "Maximize" via the group API.
- D2. Pill component inside the `exoPanel` wrapper, absolutely positioned, pointer-events scoped so it never blocks the canvas. Collapses to glyph-only under ~240px pane width. Touch targets ≥ 44px on mobile.
- D3. Manifest gets `menu?: MenuItem[]` and `toolbar?: boolean` so the pill knows what to show. Migrate json-edit's ad-hoc ☰ and the `panel-toolbar` divs onto it.
- D4. Per-pane status dot in the pill, driven by real per-pane state (does not exist yet; add a per-panel-id map on the bus or the OSC channel layer). Until then the dot is identity only (glyph + accent), which is honest.
- D5. Theme: Harold explores the prebuilt classes; we expose the choice in Settings and persist it. Spike `-spaced` variants, which suit the pill (gaps between groups).

## What might be missing (open questions for Harold)
1. Drag handle. If the group header is hidden for single-tab groups, the tab is gone and so is the drag source. The pill must become the drag handle or DnD is lost.
2. Maximize. Dockview has `api.maximize()` per group; worth a pill menu item on mobile.
3. Pop-out windows do not share the json-bus (in-process only). A popped-out 3D-Inspect will not follow selection. Either accept it, or relay bus events over Tauri events (the OSC path already does this).
4. Toolbar visibility should persist per pane in panel params, or it resets on reload.
5. Keyboard: pill menu needs focus/Escape handling; mobile needs long-press for the menu.
6. "+" clone action in the current left header slot: where does it go when the header hides? Pill menu, probably.
7. Status bar currently carries the only connected/decoupled toggle; when the layout is one big 3D pane on a phone, that bar costs 40px. Could move into the pill menu.
